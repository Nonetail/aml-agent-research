# Post-screen lower-context diagnostic

24 October 2026. Added after the first completed development 1,500-row responses missed their known references. This is an explicitly adaptive follow-up, not part of the original frozen size comparison. Run only after the original initial and follow-up stages finish, within their unchanged shared ceiling of 120 provider attempts and 10 million token units.

Use the same model, disabled thinking, system prompt, response schema, tokenizer, scope and exact source-row fields. Do not tune a prompt from observed answers. Make two fresh identical requests for the first 32 source-preserving rows of each development pool (three cases, six requests). These deliberately retain the positive support, as in the original 300/750-row construction. Evaluate using the original five-of-six complete-reference screening gate with zero invalid-edge or unsupported-ID claims. Report all structural oracle cycles and incidental labels as before.

Also send one core-only request for each development case (two, three or four exact reference edges, shuffled by the same fixed order). These three requests test whether the unchanged prompt/format/model can identify a complete simple cycle with virtually no clutter. They are explicitly selected minimal controls and do not measure reliability, noise tolerance, or natural prevalence.

If the 32-row development screen passes and at least six attempts remain, run two fresh 32-row requests for each of the three original held-out cases. This tests the adaptively selected small size on episodes unused for that size decision; it does not retroactively make the development screen confirmatory. If the gate fails or budget is unavailable, record that reason and do not describe the omitted confirmation as a failure or a pass.

All requests and outcomes remain in the same attempt accounting. Supplemental job lists and their script/protocol hashes are saved separately; the original manifest and results remain unchanged. A passing small-size screen is provisional evidence on these cases, never a universal safe graph size.
